Embedding

The CLI is also a library. A host process runs the same command classes in-process, supplying credentials, identity, and policy per invocation, with no process spawned and connections kept warm between calls.

Why the runtime exists

oclif is designed for one person running one command: one process, arguments from the shell, output to the terminal, exit when done. An agent runs the same commands thousands of times, often inside a process serving many agents at once, with identity and credentials arriving per request. A process per command means a login per command. aclif therefore treats the CLI as a library with a binary attached. Every execution is described by an explicit invocation, and the same command classes run under any host.

Three deployments

1. In the agent's environment

The binary sits on the agent's PATH and the agent shells out to it. Credentials come from flags, environment, or a profile; policy from the same file; the audit line on stderr. Use this when one agent, one operator, and one set of credentials share a trust boundary.

2. As a tool call

A host binds commands as functions the model can call. In-process, the host starts one Runtime and calls runtime.run(...) from its tool handler. Through an agent application, the model is given a single tool whose arguments are a command string, its flags, and a tenant instance, and the application forwards it. Use this when tool definitions must stay out of the model's context: one tool describing the grammar replaces one tool per operation.

3. As a gateway

A long-lived process starts one Runtime and serves many agents. Each request becomes an Invocation carrying the command as argv, an execution context with the user's identity and forwarded SSO claims, a credential resolver over the host's secrets store, a capability gate that runs on the command's declared metadata before its code loads, a rate-limit hook, a reporter, and the shared connection pool keyed by provider, instance, identity, and auth type. The agents hold no provider credentials and cannot widen their own scope. Use this when many agents share providers and one place must hold the policy and the audit trail.

Minimal host

import {Runtime, EventReporter, StaticCredentialResolver} from 'aclif'

const runtime = await Runtime.start({cliRoot: '/path/to/your/cli'})
const reporter = new EventReporter()
const result = await runtime.run({
  argv: ['salesforce', 'data', 'query', '--query', 'SELECT Id FROM Account LIMIT 1'],
  context: {requestId: 'req-1', user: {id: 'u1', username: 'alice'}},
  credentials: new StaticCredentialResolver(new Map([
    ['salesforce', {instanceUrl, accessToken, authType: 'session'}],
  ])),
  pool: runtime.pool,
  reporter,
  hooks: {
    capabilityGate: async ({aciMetadata}, ctx) =>
      aciMetadata.mutability === 'delete' && !ctx.user
        ? {allowed: false, error: {code: 'DENIED', message: 'Deletes need a user'}}
        : {allowed: true},
  },
})
console.log(result.exitCode, reporter.envelope())

cliRoot is the package root of the CLI whose commands the runtime should load: the framework itself for the reference binary, or your own package for a CLI built on aclif.

What the host supplies

On the invocationPurpose
contextrequest id, the acting user, forwarded SSO claims, an abort signal, audit metadata such as the calling application
credentialsa CredentialResolver. Static, Env, Profile, and Chain resolvers are built in; a vault-backed host implements the one-method interface and resolves per request
poolthe runtime's connection pool; two tenants never share a connection
reportercollects the envelope and events; EventReporter is the reference implementation
hooks.capabilityGateallow or refuse from the command's declared metadata before its code loads
hooks.rateLimitcalled per provider and operation before execution
tenantCache, aliasStoreoptional: the host's own store for tenant catalogues and alias sets, so learn, --schema, and --canonical read the host's data

Health monitoring, probe timers, and declarative manifests that turn one HTTP endpoint into a command are part of the runtime as well. The reference is EMBEDDING.md.
