Getting started

The reference CLI is the aclif binary, built with every native and contributed provider. Node 22 or later.

Install

npm install -g aclif
aclif discover --json

Or from a checkout:

git clone https://github.com/agent-cli-framework/aclif.git
cd aclif && npm install && npm run build
node bin/run.js discover --json

discover lists every provider, its tier, and whether credentials are configured. It needs no credentials itself.

Credentials

Credentials resolve in one order: command flags, then environment variables, then a named profile in the config file. Each provider declares its authentication paths once, and the flags, environment names, profile format, and error messages all follow from that declaration.

export SF_INSTANCE_URL=https://example.my.salesforce.com
export SF_ACCESS_TOKEN=...
aclif salesforce data query --query "SELECT Id, Name FROM Account LIMIT 3" --json

For anything longer than a session, put a profile in ~/.config/aclif/config.yaml. Secrets in a profile can be literal, or read from the environment, a file, or a command at credential time, so the file itself need hold no secret.

default_profile: dev
profiles:
  dev:
    salesforce:
      instance_url: https://example.my.salesforce.com
      access_token: {env: SF_ACCESS_TOKEN}

Select one with --profile dev or ACLIF_PROFILE=dev. aclif auth status shows which profile and credentials are in effect without printing a secret. The full reference is CONFIGURATION.md.

Learn a provider, then a command

aclif learn salesforce --json                  # topics, key fields, query syntax, auth paths
aclif salesforce data query --schema           # flags, args, safety metadata
aclif salesforce data query --examples         # runnable examples with the responses they produce
aclif salesforce data query --shape            # the structure of a successful result
aclif salesforce data query --estimate         # rough token cost per record

Every introspection flag returns before the command executes and works with an empty environment. This is the property that lets an agent load a command's definition only at the moment it needs it.

Run, safely

aclif salesforce data query --query "SELECT Id FROM Account LIMIT 1" --dry-run
aclif salesforce data dml --operation delete --object Account --ids 001xx --confirm

Every mutation accepts --dry-run. Commands whose declared metadata marks them as deletes, as touching all records, or as executing code on the target require --confirm, and the policy layer enforces that before the command's code loads. After every run an audit line lands on stderr naming the command, the user, and the exit code.

Read the result

FieldHolds
successtrue or false
resultthe records or the provider's response
_context.paginationreturned, total, hasMore, and nextCommand, a complete command string for the next page
_context.relatedCommandscomplete command strings worth running next
erroron failure: code, message, a hint naming the command that fixes it, and where possible a corrected value

Exit codes are 0 for success, 1 for an API failure, 2 for a usage error, and 3 for missing or rejected credentials, so an agent can branch without parsing prose. The full contract, with the JSON Schemas that validate every envelope, is CONTRACT.md. The agent-facing quick start is AGENTS.md.

Give an agent the binary

Put aclif on the agent's PATH the way a coding agent has git. Point the agent at AGENTS.md, or tell it to start with aclif discover --json and use --schema and --examples before running anything. The repository Dockerfile builds a standalone image for this deployment.
